# GLH v0.6.19 — دليل النسخة المطوّرة

## 1) محتويات المشروع
- `web/`: واجهة العميل والإدارة والبوابات والملفات الثابتة.
- `server/`: خادم Node.js/Express وواجهات API.
- `server/prisma/schema.prisma`: مخطط قاعدة PostgreSQL.
- `server/prisma/seed.js`: بيانات التهيئة الأولية.
- `server/test/`: اختبارات Node المضمنة.
- `docker-compose.yml` و`Dockerfile` و`render.yaml`: ملفات التشغيل والنشر.
- `scripts/`: أدوات التشغيل المحلي والنسخ الاحتياطي والاستعادة.

## 2) تحديثات واجهة العميل في 0.6.19
- شريط علوي أفقي، وقائمة خدمات جانبية رأسية على الشاشات الكبيرة.
- على الهاتف تتحول القائمة إلى شبكة تنقل من ثلاثة أعمدة.
- شبكة الخدمات في الرئيسية والوحدات التشغيلية المتقدمة من ثلاثة أعمدة، مع استجابة للشاشات الصغيرة.
- فصل التسجيل ودخول العميل والتسجيل كتاجر ورابط «بوابتي» داخل مساحة الحساب والبوابة.
- عدم عرض اختصارات الخدمات المالية والمجتمعية أو بوابة العميل والتاجر ضمن قائمة الخدمات الرئيسية.
- إضافة صفحة «الوحدات التشغيلية المتقدمة» تربط المستخدم بمسارات العميل الموجودة فعلياً.
- الوحدات الداخلية الإدارية لا تمنح صلاحياتها من واجهة العميل؛ يجب الدخول بحساب مخوّل من واجهة الإدارة.

## 3) المتطلبات
- Node.js 20 أو أحدث.
- npm.
- PostgreSQL 14 أو أحدث، أو Docker Desktop لتشغيل Docker Compose.
- متصفح حديث.

## 4) التشغيل المحلي باستخدام Docker
من مجلد المشروع:
```bash
docker compose up --build -d
```
ثم افتح:
- `http://localhost:4000`
- فحص جاهزية الخادم: `http://localhost:4000/api/ready`

لإيقاف الخدمات:
```bash
docker compose down
```
لا تستخدم `docker compose down -v` إلا إذا كنت تقصد حذف مجلد بيانات قاعدة البيانات.

## 5) التشغيل اليدوي
1. انسخ `server/.env.example` إلى `server/.env`.
2. عيّن `DATABASE_URL` و`JWT_SECRET` وكلمة مرور مدير أولي قوية عبر `SEED_ADMIN_PASSWORD`.
3. من جذر المشروع:
```bash
cd server
npm install
npx prisma generate
npx prisma db push
npm run db:seed
npm test
npm start
```
4. افتح `http://localhost:4000`.

## 6) إعدادات البيئة
راجع `server/.env.example` و`.env.example`. لا ترفع ملفات `.env` أو كلمات المرور أو مفاتيح التكامل إلى GitHub.
يجب استخدام `JWT_SECRET` عشوائي طويل وفريد، وتغيير كلمة مرور المدير التجريبية قبل أي نشر.

## 7) الاختبارات المنفذة على الحزمة
تشغيل:
```bash
cd server
npm test
```
تغطي الاختبارات العقود البرمجية، صلاحيات الوصول، واجهات الإدارة، مسارات الأعمال، والواجهة المحدثة. هذه اختبارات آلية على مستوى الشيفرة وليست اختبار قبول تشغيلياً على قاعدة بيانات إنتاج أو على هاتف فعلي.
للتحقق من مخطط قاعدة البيانات:
```bash
npx prisma validate
```
ولفحص اتصال قاعدة البيانات بعد التشغيل افتح `/api/ready`.

## 8) الرفع إلى GitHub
أنشئ مستودعاً خاصاً أو فرع إصدار منفصلاً، ثم من جذر المشروع:
```bash
git init
git add .
git commit -m "GLH v0.6.19 client UI refresh"
git branch -M main
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main
```
إذا كان المشروع مربوطاً بمستودع قائم، لا تنفذ `git init` أو تستبدل `origin` قبل مراجعة إعدادات المستودع والنسخ الاحتياطي.

## 9) النشر على Render
استخدم `render.yaml` كمرجع إعداد، أو أنشئ Web Service مع PostgreSQL. تأكد من ضبط `DATABASE_URL` و`JWT_SECRET` و`NODE_ENV=production` وبيانات مدير أولي آمنة. راجع `INSTALL_GITHUB_RENDER_AR.md` و`README_RENDER_AR.md` قبل النشر.
بعد النشر اختبر `/api/health` و`/api/ready`، ثم اختبر التسجيل وتسجيل الدخول وإنشاء الطلب ومتابعته بحسابات وأدوار مختلفة.

## 10) حدود الإصدار
- لا يعني نجاح الاختبارات أن جميع التكاملات الخارجية تعمل؛ خدمات الدفع والبنوك وSWIFT والشحن والجمارك تحتاج عقوداً وبيانات اعتماد وبيئات Sandbox واختبارات مزود.
- بطاقة المستثمر تعريفية/توجيهية، ولا يضيف هذا التحديث دورة استثمار خلفية مكتملة.
- وحدات الإدارة التشغيلية الحساسة يجب أن تبقى محمية بتسجيل الدخول والصلاحيات؛ لا تُفتح من واجهة العميل العامة.
- لا تعتمد الإنتاج قبل مراجعة الصلاحيات والنسخ الاحتياطي والأمان واختبارات UAT.
